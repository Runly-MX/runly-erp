# Motion Engine and Responsive Pro (Phase 3) — Implementation Plan

Spec: `docs/superpowers/specs/2026-11-23-motion-and-responsive-pro-design.md` (Proposed; implementation starts on approval).

## Goal

Ship Phase 3 as ONE release train: Atlas 0.10.0 + `@runly/studio-interchange` + ERP + Hub, adopted and verified end to end BEFORE anything is published, so the publishing agent performs a single publication and no follow-up patches are needed.

## Working rules for this plan

- No intermediate publishes. Every task commits locally on `main` of its repo; nothing is pushed until Task 9 passes.
- Every task ends with its own validation command and leaves all three repos green (`pnpm test` in Atlas, interchange suite, Hub unit suite, ERP touched suites).
- A defect found by a later gate is fixed inside this train (new commit), never as a post-publish patch.
- Agent usage: Tasks are executed inline by one agent; at most one reviewer pass on Task 9 evidence (token economy).

## Architecture summary

1. **Universal props contract** (Task 1): Atlas exports `UNIVERSAL_PROPS` (specs + ranges) next to `effects.js`; the catalog generator writes `universalProps` and `capabilities`; interchange gets a pure `website-effects.js` that validates `_*` props from the catalog; parity test ties both. Hub/ERP read the catalog they already load.
2. **Motion** (Tasks 2-3): SSR-safe reveal (visible by default, hidden only after hydration for below-the-fold elements via a `data-atlas-reveal` state class), extended `_animation`, `_kenburns`, `_pressed`, hover only under `(hover: hover) and (pointer: fine)`, containment against overflow, shared IntersectionObserver.
3. **Responsive Pro** (Task 4): fluid type (`clamp()`), theme `fluid` tokens, focal point per device, shared measurement rules for overflow.
4. **Editor** (Task 5): Inspector controls reusing existing field system.
5. **Hosts** (Tasks 6-7): interchange reader/writer, Hub diagnostics and contract descriptors, ERP admin contract and release behavior.
6. **Verification** (Tasks 0, 8, 9): real-browser matrix script reused by all repos; Phase 2 acceptance first; rehearsal with packed artifacts.

## Task 1 — Universal props contract (Atlas) and parity

- [ ] `universalProps.js`: spec table for `_animation`, `_kenburns`, `_pressed`, `_stagger`, `_parallax`, `_hover`, `_transform`, `_filter`, `_opacity`, `_cursor`, `_zIndex`, `_lazy`, `_lazyMinHeight`, with ranges from the spec section 10; `validateUniversalProp(name, value)` returns `{ ok, value, error }`; `effects.js` sanitizers delegate to it so render and validation share one source.
- [ ] Catalog generator (`generate-website-block-catalog.mjs`) writes `universalProps` and `capabilities: { motion: 1, responsive: 1 }`; tests assert the catalog digest changes only through these keys.
- [ ] Interchange `website-effects.js`: pure port (no React) + `checkBlock` validates props starting with `_` through the catalog's `universalProps` (unknown `_x` -> `effect_unknown`, out of range -> `effect_invalid`); writer unchanged apart from passing props through.
- [ ] Parity test: loads Atlas `universalProps.js` (workspace path in the rehearsal, packed tarball in CI) and the interchange module; same fixtures + boundary fuzz must give identical results.
- Validate: `pnpm test` (Atlas), `node --test packages/studio-interchange/src/__tests__/website-effects*.test.js`.

## Task 2 — Motion Engine runtime (Atlas)

- [ ] SSR-safe reveal: server output is visible; `ScrollRevealWrapper` marks below-the-fold elements hidden only after mount using a class (`atlas-reveal--pending`) set in an effect before first paint (`useLayoutEffect` guarded for SSR), never inline `opacity:0` from the server; above-the-fold (first `eagerBlocks`) uses entrance-on-load or no hiding.
- [ ] Extended `_animation` (distance, scaleFrom, blur, once) mapped to CSS custom properties consumed by keyframes in `elements.css`/new `motion.css`; `once:false` replays when re-entering.
- [ ] `_kenburns`: clipped frame (`overflow: clip`, `contain: paint`), CSS animation with custom properties, applied to ImageBlock/ImageElementBlock/Hero background via `EffectsWrapper`; off under reduced motion, edit mode and print.
- [ ] Hover under `@media (hover: hover) and (pointer: fine)`; `_pressed` via `:active`; `:focus-visible` outline baseline for interactive blocks; `@media (prefers-reduced-motion: reduce)` and `@media print` kill effect animations/transitions.
- [ ] Shared `RevealObserver` (one observer per threshold), disconnect on once, `will-change` only while animating; parallax clamps to declared range and sits in a clipped wrapper.
- Validate: `motionSsr.test.jsx` (server HTML has no hiding, hydrates, reduced-motion), `kenBurns.test.js`, existing `effects.test.jsx` still green.
