## Defects found by the rehearsal and fixed inside this train

1. Cross-origin tinted SVG rendered an empty box when the origin sent no CORS headers (fixed: plain image until the browser confirms CORS).
2. The focal-point field was a generic design field, so it appeared on every element and created a stray collapsed "Contenido" inspector
   section that hid the text field after selecting a text element (found by the existing Hub Frame browser test; fixed, plus an Atlas unit test
   and an editor step in the browser matrix so it cannot come back unnoticed).
3. Ken Burns was offered on text boxes because every element has an optional background image (fixed: only image-content blocks).
4. New reader error codes (`effect_*`, `svg_*`, `component_*`, `fluid_invalid`) were not in the Hub diagnostic registry, so MCP clients saw
   `INTERNAL_ERROR` instead of the real cause (fixed and pinned by a test).
5. The catalog adoption script duplicated registry entries when run twice for the same version (fixed: idempotent per version).

## Failures that are NOT part of this release (unchanged by it)

- ERP services: `files visibility`, `help capabilities.json`, `runtime catalog matches the installed versions`, `all manifest permissions are
  explicit in PERMISSION_CATALOG`, `fallbacks do not recreate an old name` fail on a clean checkout too.
- Hub `toolchain-compat` fails after every shared-package pin bump until `node scripts/gen-toolchain-compat.mjs` is rerun (step 5 below).
- Hub tests that compare package.json, lock and installed packages (`all shared packages match provenance...`, `adopted Atlas and all eight
  installed shared packages...`, registry preflight and lock-shape tests) can only pass after the real adoption commit.
- The Postgres release tests of the ERP need a disposable runner and were not run here.

## Hand-off: single publication, in this order

1. **Atlas** (`atlas-web-builder`, commit `cf0a7c7` or later with the same `dist` hashes): push `main`, `npm publish` 0.10.0, tag `v0.10.0`.
   Check that the published `dist` hashes equal the table above.
2. **ERP**: push `main`; run the protected shared-packages workflow. Note the resulting source revision `R`.
3. **ERP adoption commit**: bump `@raulbellosom/atlas-web-builder` to `0.10.0` in `apps/api`, `apps/desktop`, `packages/website-blocks` (and the
   workspace override) and the shared package aliases to `R`; `pnpm install`; then
   `node scripts/generate-website-block-catalog.mjs` and
   `node ../runly-developer-hub/scripts/adopt-website-catalog.mjs --version 0.10.0 --erp . --revision <ERP commit sha> --write`.
   Confirm the two digests printed match this file. Commit the ERP side (catalogs, registry, lock).
4. **Hub adoption commit**: bump the Atlas dependency and override to `0.10.0`, set the shared pins and `shared-packages.lock.json` to `R`
   (same procedure as the previous adoptions) and keep the files written by the adoption script.
5. `node scripts/gen-toolchain-compat.mjs` in the Hub and rebuild the validator root for `R` (`prod:update` does it in production).
6. **Gate after adoption** (all must pass): ERP `node --test packages/studio-interchange/src/__tests__/*.test.js`; ERP

   Hub `node --env-file=.env --test --test-concurrency=1 tests/integration/*.test.js`.
